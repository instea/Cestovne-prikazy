1. Overview

Internal Instea web app with three jobs: (a) record business trips and generate Slovak travel-warrant xlsx files with per-diem; (b) let employees request leaves and admins approve them; (c) expose a monthly attendance API (Toggl hours plus leaves) for machine clients. Users are Instea employees signing in with Google, admins, and M2M consumers (README.md:1-11, README.md:106-117).

Node server

Express 4, express-graphql, Mongoose. Port 4100 is hardcoded (server/index.js:24). CLI mode --email promotes a user to admin.

React SPA

Trips, Places, Users, travel-warrant export. Redux, Apollo 1.x, redux-form, Bootstrap 3.

Angular SPA

Leaves list, calendar, add, approval, summary, detail export. ngrx 2, Apollo 2, PrimeNG.

Shared src/data

Enums, converters and diet tariffs used by server and React. Angular keeps its own copies ("keep in sync").

Server middleware chain (server/index.js)

/download (public static) → cors() → POST /refresh-jwt + express-jwt (optional) + user loader
→ /graphql (graphiql:true) → /api/* basic auth → /health-check → POST /export/*
→ /leaves/ Angular dist → / React build

2. Functional spec

Features by area

Auth & session
  • Users sign in with Google. The client sends the ID token to the loginUser mutation (server/graphql/userRelated.js:21-68).
  • Outcomes: SUCCESS + JWT (1 h) for approved users; NEED_APPROVAL for unapproved users, and new users are auto-created unapproved; WRONG_DOMAIN if hd ≠ HOSTED_DOMAIN; FAILED when token verification fails.
  • Both SPAs keep the JWT in localStorage.jwt and refresh it every 15 min via POST /refresh-jwt.
  • The first admin is created via CLI: yarn promote-user --email=<google_email> (README.md:60-69).
Trips (React)
  • Lists all trips of all users, sorted by departure (tripRelated.js:17-18).
  • Add or edit: Who, Where, departure, arrival, purpose, travel type, price. Defaults are yesterday 08:00–17:00, type O.
  • Duplicate: pick a new departure. Arrival = new departure + original duration.
  • Edit, Remove and Duplicate buttons show for the owner or an admin. bug The server lets only admins edit or remove.
Places (React)
  • All users can view places. Admins add, edit and remove them. Fields: name, destination, origin, travel duration (slider 0–24 h, 15 min steps), country (default SK).
Users (React)
  • Admins list, edit, remove and approve users. Each user edits their own profile (names, degrees, address). A deleted user shows as "Deleted <id>".
Travel-warrant export (React /export)
  • Pick a user and month, then Generate. The server fills an xlsx template with trips and per-diem, and a Download button appears.
Leaves (Angular /leaves/)
  • List or calendar of all users' leaves, filterable by requester, month and year.
  • Add: type, start, end, half-day, with the work-day count computed live. The server forces PENDING and emails the approver.
  • Delete: the server allows it only for the requester or an admin. Approval page (admin): Approve / Reject, with a pending badge in the nav.
  • Summary: your own leaves per year and type. Detail export: trip days, leave days, expected meal vouchers.
Attendance API (M2M)
  • GET /api/attendence/:year/:month returns daily Toggl hours and leave codes per employee from the SSO directory.
Ops
  • /health-check pings Mongo. There are no cron jobs.

Each trip fills a left row (Bratislava + date, place, purpose) and a right 4-row block (dates, origin/destination, times shifted by travel duration, travel type, price, diet). Excel recalculates the formulas.

Meal vouchers (detail export)
working day  = not Sat/Sun and not an SK holiday (date-holidays 'SK')
halfDays     = count(isHalfDay leaves) / 2
leavesCount  = |leaveWorkingDays| − halfDays
vouchers     = |monthWorkingDays \ tripDays \ leaveDays| + halfDays

Example: 21 − 3 trip days − 3 leave days + 0.5 = 15.5. Caveats: all leave states count, and the 1st of the next month is included.

Test cases (Dec 2017): trip 24→27 → [27]; trip 8→11 → [8, 11].

Work-day count & leave filter (Angular)
  • Inclusive range, skipping weekends and SK holidays; half day subtracts 0.5. Tests: 2017-12-07..11 = 3; 2017-12-22..30 = 4; 2017-12-11..13 half day = 2.5.
  • Filter: requester ∈ selected; a leave is split per calendar year, and it matches if any segment covers a selected year or month.
  • Calendar: colour per requester (15-colour palette), pending shown at 50 % opacity, rejected hidden.
Attendance codes

Only APPROVED leaves on working days count. ANNUAL → D8 (D4 for a half day), SICKNESS → PN, DOCTOR → L, others → I; several codes on one day are joined with ", ". Hours = Toggl seconds / 3600 per day.

Acceptance criteria (main flows)

Auth
  • Given a new domain account, when it logs in, then an unapproved user is created and "Account needs to be approved by admin first." is shown.
  • Given another domain, then WRONG_DOMAIN is returned and no user is created.
  • Given an approved user, then the JWT is stored and refreshed every 15 min.
Trips & export
  • Given a trip 08:00–17:00 duplicated at D, then a new trip D → D+9h exists.
  • Given 3 / 12 / 16 trips in a month, when exported, then upto19 / upto31 / "Problem preparing file".
Leaves
  • Given end < start, then "Start date must not be greater than end date" and Add is disabled.
  • Given a valid leave, when it is added, then it is PENDING, the approver is emailed, and the app navigates to /list.
  • Given an admin on approval, when Approve is clicked, then state = APPROVED and approver = admin.
Attendance & ops
  • M2M credentials unset → 401. A non-numeric month → 400 "Month is not a number.".
  • Mongo down → /health-check returns 500.

5. Deployment

  • A single multi-stage Docker image (Dockerfile): node:8 builds Angular (base href /leaves/) and React; the node:12.22-slim runtime runs node server/index.js on port 4100, with a /opt/app/secrets/ volume.
  • Jenkins builds cestaky:master and runs docker-compose up -d in $DEPLOY_DIR. The compose file is not in the repo.
  • Alternative: a PM2 ecosystem (PM2.md). The k8s restart behaviour is mentioned only in a code comment (server/db/connect.js); there are no manifests in the repo.
  • Environments: dev (CRA proxy / Angular → localhost:4100) and production (NODE_ENV=production, same origin). No staging.
